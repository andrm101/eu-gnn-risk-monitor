Phase 2B — What connects two NUTS2 regions?

Edge type is the most fundamental graph design decision. It determines what the GNN can "learn" about neighbourhood effects.

A

Spatial adjacency only (Recommended)

Two NUTS2 regions are connected if they share a land border. Edge weight = 1 (unweighted) or inverse distance between centroids.

Pros

  • Standard in GNN-on-NUTS literature — directly comparable to published work
  • Derived automatically from the GISCO GeoJSON already in the project
  • Captures labour market spillovers and migration corridors realistically
  • Homogeneous graph → simpler GNN architecture (GCN, GraphSAGE)

Cons

  • Misses non-contiguous linkages (e.g. island regions, sea crossings)
  • Treats all borders equally — a DE/PL border ≠ a FR/LU border in economic terms
B

Spatial adjacency + economic similarity edges

Add a second edge type connecting the k=5 nearest neighbours in feature space (GDP, unemployment, IHPI). Two edge types → heterogeneous graph.

Pros

  • Captures non-geographic linkages (e.g. Warsaw ↔ Prague economic cohesion)
  • Richer signal for GNN — can model "structural equivalence" across EU

Cons

  • Requires a heterogeneous GNN (R-GCN, HAN) — more complex Phase 3
  • kNN in feature space is sensitive to feature scaling and choice
  • Harder to explain in methodology section
C

Spatial adjacency with weighted edges

Shared-border adjacency, but edge weight = f(shared border length, centroid distance). Homogeneous weighted graph.

Pros

  • More nuanced than binary adjacency — long shared borders = stronger link
  • Still a homogeneous graph → simpler GNN
  • Border length derivable from GISCO shapefile

Cons

  • Marginal gain over unweighted in most GNN benchmarks
  • Border length computation adds non-trivial geopandas intersection logic
